# brainstorm

## When to use
User request is ambiguous, multi-way, or lacks a single obvious path.

## Steps
1. Restate the goal in one sentence.
2. List 2–4 concrete options (include “do nothing / defer” when relevant).
3. For each option: pros, cons, risk, estimated effort.
4. Recommend one option with explicit rationale.
5. Ask for confirmation only if the decision changes architecture or scope; otherwise proceed with the recommendation and record it in progress.md.

## Output
Short structured note (options table or bullets) written into progress.md or the active feature notes. Do not start coding until a direction is chosen.
